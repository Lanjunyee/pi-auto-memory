- 已发布对照：`0.1.1` 已包含 `/memory list` 和 `/memory reload`，没有 `/memory doctor`。`0.1.0` 只有 status/on/off/edit/delete。
- 本文仅随公开源码分发，npm 包内不包含 `docs/`。截至核对日期，公开 `main` 尚无 `docs/`，因此 README 中的远端指南链接暂不可用；更新公开源码前请以本地候选源码为准。
- 仅支持 pi 1.2.0 独立主会话，Node.js ≥22.19.0。本轮没有执行真实模型调用，也没有在本轮重新实测本文全部步骤。
- 候选新增简体中文的菜单、用法、状态、开关、通知和诊断原因；步骤中的中文措辞以对应候选构建为准。本变更验收见本地记录，发布前需重新核对。

## 从候选公开源码启动

在已审查的候选公开源码根目录准备依赖，再执行以下命令。核对仓库版本，当前公开 `main` 不一定是候选；不要同时加载安装包和源码入口。

```sh
npm ci --ignore-scripts
repo="$PWD"
sandbox=$(mktemp -d /tmp/pi-auto-memory-trial.XXXXXX)
mkdir -p "$sandbox/project" "$sandbox/agent"
printf '%s\n' "$sandbox"
cd "$sandbox/project"
env -i PATH="$PATH" HOME="$sandbox" TERM="${TERM:-xterm-256color}" \
  PI_CODING_AGENT_DIR="$sandbox/agent" PI_OFFLINE=1 \
  node "$repo/node_modules/@earendil-works/pi-coding-agent/dist/bundle/cli.js" \
  --offline --no-extensions --extension "$repo/src/index.ts" \
  --no-skills --no-prompt-templates --no-themes --no-context-files --no-mcp --no-session
```

只输入下列 `/memory` 管理命令，不提交自然语言模型任务。没有模型或认证提示不影响离线管理；不要在此环境添加日常认证。预期加载一个 memory 扩展，不出现扩展加载错误。

## 管理步骤与预期结果

以下结果为预期，不等于本轮已实测通过。命令名、诊断检查标识和 `ok`／`warning`／`failure`／`unchecked` 保留原样。

1. `/memory status`：显示记忆已开启、当前临时项目路径，以及快照尚未加载。预期出现中文说明，包含“同一 agentDir（Pi 用户目录）下的所有项目共用开关，记忆文件按项目隔离”；不读取正文。
2. `/memory doctor`：显示只读分项诊断。初始没有记忆目录／索引是正常状态；`rg`、`fd`／`fdfind` 缺失只影响相应扫描，不能因此认为全部通过。诊断不创建正文、不修改开关、不解除工具暂停。预期原因和建议为中文，检查标识保持稳定。
3. `/memory off`，再执行 `/memory reload`：关闭成功；预期中文提示说明开关影响当前 agentDir 下所有项目、其他会话在下一任务或访问检查时感知，文件与历史保留。刷新应被拒绝并提示先开启。执行 `/memory on` 后开关恢复，不会立即加载索引；提示同样说明作用范围和延迟感知。
4. 在另一个终端仅向上面打印的临时项目记忆目录写入合成 `topic.md`，例如 `synthetic baseline`；目录位置取自 status。首次目录不存在时自行创建该临时项目目录，权限设为 700，合成文件设为 600。不使用真实个人信息或秘密。
5. `/memory list`：预期显示中文文件列表；选择 `topic.md` 后只读查看，界面中修改不保存；退出查看后重新列出文件，取消列表退出。没有独立 view 子命令，空目录只显示暂无文件提示。
6. `/memory edit topic.md`：将合成文字改为 `synthetic edited` 并保存，重新打开应看到新内容。预期成功提示说明文件已保存、主题仍按需读取，不宣称已进入当前模型请求。编辑器的提交／取消键以界面提示为准。
7. 编辑 `MEMORY.md`（如果当前临时项目已有索引；没有时先按需创建合成索引）：保存成功后，预期提示磁盘变更已完成、当前快照不会自动刷新，需要 `/memory reload` 并在下一用户任务生效。不要在此步等待界面自动更新索引注入。
8. `/memory delete topic.md`：先拒绝一次确认，文件应保留；再次调用并确认，文件才删除。确认界面预期包含目标文件、单文件范围、“本扩展不提供撤销”、历史仍保留且未来可能重新记住；没有整库清空或 force 删除。
9. `/memory reload`：开启且健康时仅安排下一用户任务刷新、撤销旧许可，不立即读取正文或调用模型。预期提示说明 reload 不等于完整扩展重载，也不解除工具兼容暂停；已完成的提交不回滚。
10. `/memory` 打开管理菜单：预期菜单项为中文（如“查看状态”“诊断”“列出文件”“刷新”“开启”“关闭”“编辑文件”“删除文件”等，实际文字以构建为准）。选择 Doctor 应取得与显式命令一致的中文只读诊断；取消菜单不修改状态。
11. 在不支持子代理提示或兼容暂停场景中，预期给出按序恢复建议：检查冲突项、停用冲突扩展、完整重载 Pi 扩展取得新实例、再次检查。未知冲突来源只报告未知，不猜测扩展名称。

## 请求投影与工具冲突的离线补充验证

上述手工管理不提交模型任务，因此不能单凭菜单观察下一请求的索引投影或迟到注册保护。可在候选源码根目录运行既有合成宿主回归：

```sh
node --import tsx --test tests/commands.test.ts tests/registration.test.ts tests/lifecycle.test.ts tests/lifecycle-owner.test.ts tests/managed-tools.test.ts
```

预期验证：reload 后下一任务采用新索引、旧编辑与排队提交被撤销、六名称初始／迟到覆盖与缺席后新增被检查、标准 schema 普通文件可委托而记忆调用拒绝、未知 schema 全拒绝、扫描记忆祖先拒绝、冲突后停止当前记忆投影。合成测试通过不代表中文界面或任意真实扩展组合已验收。

工具暂停在同一扩展实例内保留。doctor、on/off、reload 或会话重置都不能解除；停用冲突扩展并完整重载扩展产生健康新实例后，才按持久开关恢复。不要为手工验收加载日常第三方扩展。

## 失败、退出与保留

加载错误先检查候选是否完整、依赖是否已安装、宿主是否为 1.2.0、是否重复加载入口。doctor 仅报告问题，不自动修复。遇到配置损坏、路径拒绝、兼容暂停或保存错误，应记录安全错误类别与下一步，不把操作记为成功，不复制秘密到日志。

退出宿主即停止这次显式源码加载；临时目录保留。此方式没有安装引用，不需要卸载。若另行在临时环境安装候选包，应使用原来源执行 `pi remove`，再核对加载引用已移除、合成记忆仍存在；自动包级检查覆盖该安装／卸载路径。

关闭和卸载都保留文件与已有会话历史；删除文件不保证永久忘记。只清理确认属于本次的 sandbox，绝不清理日常 agentDir。本轮无真实模型调用、无日常扩展修改、无发布或推送；Linux、其他宿主、中文界面实测和 hosted CI 的结果需另行取得证据。
